# 리뷰 전문 기준 재검토

기준 리뷰 전문: `../review_inputs/transcripts/thesis_presentation_20260608_134813.txt`

검토 대상: `paper/석사학위논문_박현근_심사위원피드백후_최종수정본.md`

작성일: 2026-06-09

## 결론

전체 재작성은 필요하지 않다. 다만 Windows DOCX로 넘기기 전, 본문 내용 기준으로는 제4장 표 배치와 해석 문단, 초록/기여 문장의 AVM 스토리, 제2장 XAI 비중을 보강하는 것이 안전하다.

현재 수정본은 위험 용어 제거, 시공간 이질성 축소, `연도별·권역별` 표현 전환, 강남3구/비강남 한계, 직선거리 한계, SHAP 비인과성, 표·그림 번호 정합성은 대체로 반영했다. 남은 리스크는 새 분석 부족 자체보다, 심사위원이 요구한 "해석이 먼저 나오고 표는 근거로 따라오는" 서술 구조가 아직 충분히 강하지 않다는 점이다.

추가로 `cc` Claude Code 재검토는 본문 보강 3개에 더해 Word 산출 전 검수 항목까지 포함해 DOCX 전 필수 점검을 6개로 보았다. 해당 원시 결과는 `.omx/artifacts/ask-claude-thesis-full-transcript-review-cc-20260609.md`에 저장했다.

## Windows DOCX 전 필수 보강

아래 3개는 본문 내용 자체의 필수 보강이다. `cc` Claude Code 재검토는 여기에 직선거리 선택 사유, 단지 대표좌표 한계, 수식/front matter/체크리스트 정합성 같은 DOCX 전 점검까지 합쳐 총 6개로 확장했다.

### 1. 제4장 표가 여전히 소제목 직후에 너무 빨리 나온다

- 근거: 리뷰 전문 71-87행에서 무작위/단지/시간 분할, 시나리오 A/C, SHAP 순위, 연도별·권역별 표에 대해 "표는 다 있는데 해석 글이 없다", "해석을 먼저 쓰고 그 다음 표를 넣으라"고 반복 지적했다.
- 현재 원고: 최종본 545-549행, 594-598행, 713-717행, 751-755행, 771-775행, 789-793행은 소제목 뒤 1-2문장 후 바로 표가 나온다.
- 판단: 형식 검증은 통과했지만 심사위원 요구 수준으로는 약하다.
- 조치: 각 핵심 표 앞에 "이 표에서 읽어야 할 결론"을 3-5문장으로 먼저 쓰고, 표 뒤에는 한계/해석을 덧붙인다. 최소 대상은 `<표 4-4>`, `<표 4-7>`, `<표 4-11>`, `<표 4-13>`, `<표 4-14>`, `<표 4-15>`이다.

### 2. AVM 갱신 스토리가 결론에서는 낮춰졌지만, 초록/기여에서는 아직 간접적이다

- 근거: 리뷰 전문 35-43행, 49행, 56-63행은 "1년 전 모델을 지금 써도 되는가", "AVM은 지속 업데이트가 필요하다"는 스토리를 차별성으로 삼으라고 했다.
- 현재 원고: 최종본 85-91행, 109-119행, 837행은 AVM 검증 필요성을 쓰지만, 실제 model-aging 실험은 하지 않았다고 낮춰 쓴다.
- 판단: 추가 실험 없이도 방어 가능하지만, 초록 첫 문단과 연구 기여 문단에서 "갱신 주기를 직접 추정하지 않았다"는 한계를 더 일찍 명시하면 안전하다.
- 조치: 초록/기여 문장에 "갱신 주기 산정"이 아니라 "시장 국면 변화 때 재검증이 필요함을 보이는 근거"라는 표현을 더 분명히 둔다.

### 3. XAI/SHAP 이론 비중은 여전히 길다

- 근거: 리뷰 전문 110-114행은 이론적 배경의 SHAP/XAI 설명을 방법론 쪽에 두고, 앞부분은 AVM 고찰 중심으로 가라고 했다.
- 현재 원고: 최종본 241-285행에 XAI 개념, 방법론, SHAP 수식, 시각화 설명이 독립 절로 남아 있다.
- 판단: 치명적 오류는 아니지만, 심사위원의 형식/구성 피드백을 완전히 따른 상태는 아니다.
- 조치: 시간이 있으면 제2장 XAI 절을 줄이고, AVM/부동산 가격 예측 선행연구 문단을 앞쪽에 강화한다. 시간이 없으면 Windows DOCX에서 해당 절을 너무 부각하지 않도록 분량을 줄이는 방향이 안전하다.

## cc Claude Code 재검토 추가 지적

### 직선거리 선택 사유는 한계 설명과 분리해야 한다

- 근거: 리뷰 전문 49-51행은 직선거리 사용 이유와 한계를 함께 요구했다.
- 현재 원고: 직선거리의 정의, 1.35 보정계수, 네트워크 거리 미사용 한계는 설명되어 있지만, 왜 직선거리를 선택했는지에 대한 적극적 정당화는 약하다.
- 조치: 대규모 단지-시설 조합의 계산 가능성, 재현성, 단지 단위 일관성 같은 이유를 1-2문장으로 명시한다.

### 단지 대표좌표 한계가 빠져 있다

- 근거: 리뷰 전문 초반에서 단지 내 동별 위치 차이를 반영하지 못한다는 지적이 있었다.
- 현재 원고: 단지당 단일 대표좌표를 사용한다고 설명하지만, 제5장 한계에서 이 문제가 별도 한계로 정리되어 있지 않다.
- 조치: 제5장 한계에 "단지 대표좌표 사용으로 동별 접근성 차이를 반영하지 못했다"는 문장을 추가한다.

### Windows DOCX 전 수식과 front matter 검수가 필요하다

- 근거: 최종 Markdown에는 LaTeX 수식이 다수 포함되어 있고, 표제지·제출서·인준서·연구윤리 서약서 등 front matter는 Markdown 본문에 포함되어 있지 않다.
- 판단: 논문 내용 오류는 아니지만 Word 변환 단계의 실제 산출물 리스크다.
- 조치: `WINDOWS_DOCX_HANDOFF.md`에 수식 OMML 변환 검수와 front matter 삽입 확인 항목을 추가했다.

## 방어용/선택 항목

### model-aging 또는 rolling-window 실험

- 리뷰 전문 35-43행, 61-63행의 가장 강한 아이디어는 "과거 모델을 미래에 적용했을 때 몇 년 뒤 성능이 떨어지는가"이다.
- 현재 원고는 이 실험을 하지 않았고, 837행과 849행에서 갱신 주기 직접 추정은 하지 않았다고 낮췄다.
- 판단: 필수는 아니지만, 방어 때 가장 먼저 질문이 나올 수 있다. 추가 분석을 하지 않으면 "본 연구는 갱신 주기 산정 논문이 아니라, 시점 정합과 분할 검증을 통해 지속 검증 필요성을 보인 연구"라고 답해야 한다.

### 제목에서 `거리 기반 접근성`을 계속 둘지

- 리뷰 전문 21-25행은 거리/GIS 자체가 차별성이 아니라고 했다.
- 현재 제목은 `거리 기반 접근성과 시점 정합`을 전면에 둔다.
- 판단: 거리 기반을 "신규성"으로 주장하지 않으면 방어 가능하다. 더 보수적으로 가려면 제목을 `시점 정합과 시장 국면별 예측 안정성` 중심으로 바꾸는 선택지가 있다.

## 최종 판단

전체 재작성 필요 여부: 필요 없다. 메시지 재정렬은 이미 상당 부분 됐고, 남은 것은 결과 장 해석 순서와 제2장 비중 조정이다.

DOCX 전 필수 보강 수: 본문 내용 보강은 3개다. 제4장 표 전 해석 문단 강화, 초록/기여의 AVM 갱신 스토리 명확화, 제2장 XAI 비중 축소 또는 AVM 선행연구 강화가 핵심이다. `cc` 기준으로 Word 산출 전 점검까지 포함하면 필수 점검은 6개다.

가장 큰 남은 리스크: 심사위원이 "해석이 없다"고 지적한 부분이 아직 구조적으로 완전히 사라지지 않았다는 점이다.
